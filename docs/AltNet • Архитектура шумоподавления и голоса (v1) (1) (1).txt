# AltNet • Архитектура шумоподавления и голоса (v1)

## 1) Зачем и что считаем “хорошим звуком”

**Цель:** чтобы в голосовых/видеозвонках AltNet голос звучал чисто в любых условиях: вентиляторы ПК, УФ-лампы, кондиционер, улица, эхо комнаты, музыка из колонок собеседника.
**Критерии UX:** речь разборчива, фон мягко приглушён, нет “металлических” артефактов, задержка не ощущается, кнопки простые: *“Шумоподавление: Сбаланс./Сильное/Музыка”*, *“Подавление эха: Вкл.”*, *“Автогромкость: Вкл.”*.

## 2) Общее видение (человеческим языком)

Пока вы общаетесь, AltNet на **вашем устройстве** в реальном времени:

1. Забирает звук с микрофона.
2. Убирает низкочастотный гул и выравнивает громкость.
3. **Отменяет эхо** — вы не слышите собственный голос из колонок собеседника.
4. **Глушит фон** (вентиляторы, улица, клавиатура), сохраняя речь.
5. Опционально чуть “подсушивает” комнатное эхо (дереверберация).
6. Отдаёт чистый голос в кодек (Opus) и отправляет по сети.

Никаких отправок в “облако” — **всё локально**. Модель шумоподавления и сам код — часть приложения. Обновления — только **подписанные**, без телеметрии.

## 3) Функциональные требования (v1 → v2)

* **Платформы:** Desktop (Windows/macOS/Linux), Android. (iOS — позже; PWA — через WebAudio+WASM.)
* **Режимы:**

  * **Базовый (v1):** AEC (отмена эха) + VAD (детектор речи) + RNNoise-класс (маленькая нейросеть) + AGC/лимитер.
  * **Продвинутый (v2):** выбор моделей (DeepFilterNet/FullSubNet-класс) с автоподбором по мощности устройства.
* **Задержка:** общий бюджет ≤ 60–80 мс (обработка ≤ 15–20 мс).
* **Частота/фреймы:** 48 кГц (Opus), внутренние окна 10–20 мс.
* **Конфиг по профилям:**

  * **Анонимный:** консервативные настройки, стабильность при высокой задержке сети, DTX (передаём тишину экономно).
  * **Приватный быстрый:** более агрессивное подавление и битрейт выше; быстрый джиттер-буфер.
* **Безопасность:** офлайн-инферেন্স; без голосовых слепков; очистка буферов из памяти; обновления моделей — по подписанным манифестам.

## 4) Архитектурный пайплайн

```
[Микрофон] → [HPF/преамп] → [AEC* (с link на “render”)] → [NS (RNNoise/DFNet)] 
→ [Dereverb (легк.)] → [AGC/компрессор/лимитер] → [VAD/DTX] → [Opus 48k] → [Transport]
```

* **AEC** требует “опорный” сигнал того, что воспроизводит устройство (render). Мы берём системный аудиовыход или дорожку плеера/колла — и вычитаем её из микрофона, чтобы убрать эхо.

### Блоки

* **HPF + преамп:** режем <80 Гц, убираем инфраниз; нормализуем уровень.
* **AEC (Echo Cancellation):** WebRTC AEC3 (железная база, battle-tested). На Android/iOS — используем системный *VOICE_COMMUNICATION* если оно лучше железом.
* **NS (Noise Suppression):**

  * v1: **RNNoise-класс** (около 1 МБ), WASM/NDK, очень быстрый.
  * v2: **DeepFilterNet-класс** (10–20 МБ) как “Pro-качество” на мощных ПК.
* **Dereverb:** лёгкая спектральная маска (без тяжёлых моделей) — только “подсушить” комнату.
* **AGC/компрессор/лимитер:** чтобы голос был ровный, без клиппинга.
* **VAD + DTX:** не передаём тишину; экономим батарею и трафик.
* **Opus 48 кГц:** речь/музыка, PLC/FEC настроены.
* **Transport:** WebRTC-медиа (SRTP) + наш E2E поверх сигнального уровня (стек AltNet). В групповых — позже SFU; в 1-на-1 — p2p.

## 5) Технологический стек по платформам

### Desktop/Web (SPA)

* **WebAudio + AudioWorklet** для обработки в реальном времени.
* **WASM (SIMD + Threads)** для RNNoise/DF-класса. Fallback — WebRTC-APM через встроенные флаги браузера (если доступны).
* **Отдельный Worklet** под AEC не нужен — AEC делаем либо системный (через WebRTC), либо наш со ссылкой на render-поток.

### Android

* **AAudio/Oboe** захват/воспроизведение с малой задержкой.
* **NDK**: RNNoise/DF-класс с NEON. Включаем **AEC hardware** если оно качественное; иначе — AEC3 со ссылкой на render.
* **Foreground-service** для устойчивости.

### macOS/iOS (позже)

* **AVAudioEngine**, **VoiceProcessing I/O** (встроенный AEC/NS как ещё один пресет), с возможностью “подмены” NS нашей моделью.

### Native ядро / мосты

* Ядро обработки пишем на **C++/Rust** (Rust предпочтительнее, cbindgen для C-API).
* UI (React/TS) цепляется через **WASM** или **FFI-обёртку** (в десктоп-оболочке).

## 6) Профили и предустановки

* **Пресеты шумоподавления**

  * *Сбалансированное* (дефолт): RNNoise + мягкая dereverb + AEC.
  * *Сильное*: агрессивные маски (может “кусать” речь при экстремальном шуме).
  * *Музыка*: NS минимальный, AEC в речи-режиме, компрессор мягкий.
* **Анонимный профиль**
  Больше буферов (устойчивость > минимальная задержка), DTX включён, битрейт 24–32 кбит/с по умолчанию.
* **Приватный быстрый**
  Битрейт 32–48 кбит/с, агрессивнее NS при желании, минимальные буферы.

## 7) Конфиг/UX (как видит пользователь)

* Переключатели в **настройках звонка/голоса**:
  **Шумоподавление:** *Выкл / Сбаланс. / Сильное / Музыка*
  **Подавление эха (AEC):** *Вкл/Выкл*
  **Автогромкость:** *Вкл/Выкл*
  **Тест микрофона:** индикатор уровня + “прослушать себя” (локальный монитор с задержкой ≤ 50 мс).
* Во время разговора — бейджики: “AEC активен”, “NS: Сильное”, “DTX”.
* Подробные “экспертные” опции — в расширенных настройках (скрыты по умолчанию).

## 8) Производительность и задержки

* **Окна:** 10–20 мс, перекрытие 50%.
* **Цель CPU:** RNNoise-класс — <5% на среднем ноутбуке; DF-класс — <15–25% (вкл. SIMD).
* **Алгоритмическая задержка** пайплайна: ≤ 15–20 мс. Общая (с кодеком/джиттером): ≤ 60–80 мс.

## 9) Безопасность и приватность (по доктрине)

* **Всё локально.** Никаких облачных API для шумоподавления.
* **Модели подписаны,** поставляются через обновления AltNet (SBOM/lock, откат).
* **Нет голоса “на серверах”.** Даже в групповых разговорах — минимум метаданных; E2E на сигнальном/медиа-уровне по нашему стеку.
* **Анти-фингерпринтинг:** не утекать наружу точные параметры устройства/шума; не логировать сырой звук.
* **Очистка памяти:** буферы обнуляем, отключение — глушим захват.

## 10) API ядра (эскиз, без реализации)

```ts
// TS-обёртка для Web/WASM
export type DenoisePreset = "balanced" | "strong" | "music" | "off";

export interface DenoiseConfig {
  sampleRate: 48000;
  frameMs: 10 | 20;
  preset: DenoisePreset;
  aec: boolean;            // включать AEC
  dereverb: boolean;
  agc: boolean;
}

export interface DenoiseEngine {
  init(cfg: DenoiseConfig): Promise<void>;
  // in: mono mic; render: опорный стерео/моно для AEC (может быть null)
  process(inBuf: Float32Array, renderBuf?: Float32Array | null): Float32Array;
  reset(): void;
  dispose(): void;
}
```

На native (Rust/C++) — аналогичный интерфейс, экспорт через C-ABI. Для Web — AudioWorkletProcessor ↔ WASM.

## 11) Интеграция с AltNet

* **Раздел “Серверы → Голос”** (этап 4 плана): голосовые каналы используют этот пайплайн перед кодеком.
* **Профили сети (Анонимный/Быстрый)** влияют на джиттер-буферы, DTX/битрейт и дефолтные пресеты NS.
* **UI-индикаторы состояния** в панели звонка: текущий пресет, активность AEC/AGC, предположительный SNR (оценка).

## 12) Тестирование и метрики DoD

* **Объективные:** STOI/PESQ на наборах “шум+речь” (клавиатура, вентилятор, уличный шум, музыка фоном).
* **Субъективные:** слепые прослушивания 5–7 человек, шкала MOS.
* **Производительность:** CPU/RAM на low-end ноутбуке и среднем Android.
* **Надёжность:** нет “заиканий” при пикирующем шуме, нет звона/насоса.
* **Эхо:** ERLE ≥ 30 дБ (типично), без слышимого “фидбэка”.

**Порог DoD (v1):**

* RNNoise-класс + AEC3 стабильно в реальном времени на Desktop + Android.
* UX-переключатели работают; “Тест микрофона” есть.
* SNR-улучшение ≥ 5–10 дБ на бытовых шумах; задержка ≤ 80 мс E2E.

## 13) Риски и стратегии

* **Очень шумные сцены (строительство):** “Сильное” может искажать речь. Решение: подсказка “поднесите микрофон ближе”, опция гарнитуры.
* **Слабые телефоны:** только RNNoise-класс, упрощённые окна.
* **AEC без опорного сигнала:** качество падает — предупреждаем и предлагаем надеть наушники.
* **Правовые требования стран:** вся обработка локально, модель — офлайн, исходники/лицензии открыты.

## 14) Планы по этапам внедрения

* **V1 (MVP голоса):**

  1. WebRTC AEC/NS/AGC как базовая линия (там, где это доступно из коробки).
  2. Подключить **RNNoise-класс** (WASM/NDK) и сравнить с базой; включить по умолчанию.
  3. VAD/DTX, лёгкая dereverb, пресеты, тест-монитор.
  4. Настройки по профилям сети (Анонимный/Быстрый).
* **V2:**

  1. Выбор модели (**DeepFilterNet-класс**) на десктопах.
  2. Аппаратная AEC/NS (мобильные) + наш NS как надстройка.
  3. Авто-адаптация под устройство (QoS-профили), телеметрии нет — только локальные эвристики.
* **V3:**

  1. Бимформинг для многомикрофонных массивов.
  2. Персонализированная настройка под тембр (локально, без сохранения слепков).

## 15) Почему это “почти как Krisp”, но по-нашему

Коммерческие решения используют большие обученные модели, иногда с облачной дообработкой. Мы идём путём **локального, офлайн-инференса** с оптимизированными моделями (**RNNoise/DeepFilterNet-класс**), даём пользователю **честные переключатели** и удерживаем **реальную задержку**. Итог — очень близкое к топовым сервисам качество без компромиссов по приватности и зависимости от внешних серверов.
