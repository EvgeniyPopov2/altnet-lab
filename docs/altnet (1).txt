1) Обзор модулей (что строим по слоям) L0 — Каналы: Ethernet/LAN, Wi-Fi (вкл. ad-hoc/Direct), мобильный модем, Bluetooth LE (короткие хопы), опционально LoRa (DTN-сигналы). L1 — TAL: обнаружение интерфейсов, измерение RTT/Jitter/Loss/MTU, выбор путей в рамках профиля (Анонимный/Быстрый), горячая замена канала. L2 — P2P-ткань: libp2p (Noise/TLS), PubSub (Gossipsub), E2E шифр полезной нагрузки поверх. DHT-каталоги только там, где не раскрывают лишние метаданные (локально/ограниченно). L3 — Контент: IPFS/IPLD (CID, IPNS для «человеческих» указателей), пины, кеш с LRU, общий pin-манифест сообществ, «холодное» хранение (RS-шары). L4 — Приложения: Сообщения (DM) E2E + вложения как CID; Серверы (как Discord): текст/голос/медиа/вики/файлы; Браузер .alt (статические сайты из IPFS), вкладка «Опубликовать сайт»; Конструктор сайтов (WYSIWYG)** → экспорт статического бандла (index.html + assets + manifest.json), «IPFS-готово»; Почта (адрес = ключ/алиас, «почтовые узлы» добровольцев с шифротекстами и TTL); Путешествия (каталог серверов/ботов/мини-приложений); Репутация (жалобы/метки/правила, списки white/grey/black, прозрачные решения); Профиль/Темы (светлая/тёмная, акцентные цвета, роли/стикеры/био); Помощь (wiki/FAQ/подсказки). 2) Матрица режимов и сетевых политик | Параметр | Анонимный режим | Приватный быстрый режим | | -------------------------- | ----------------------------------------- | ----------------------------------------- | | Внешний транспорт | Tor/I2P | Yggdrasil/WireGuard | | Публичный DHT | Off | Off/Local-only | | mDNS | Off | On в LAN/mesh | | Relay | Только свои (внутри Tor/I2P) | Свои в оверлее, без внешней публикации | | PubSub | Полезная нагрузка всегда E2E | То же | | Адреса Announce/NoAnnounce | Без приватных подсетей | Фильтр приватных подсетей сохраняем | | Телеметрия/метрики | Локально/опционально, без отправки наружу | Локально/опционально, без отправки наружу | Переключение профиля — 1 клик в «Профиль». 3) Хранение и долговечность Квоты: по умолчанию 5% диска под кеш; профили: 1–2% (щадящий), 5–10% (стандарт), 20–50% (зеркало сообщества). Пины: пользовательские и групповые (подписанный манифест сообщества). «Холодное» хранение: добровольные узлы принимают RS-шарды (N/M), метаданные — подписаны. Исчезновение: контент жив, пока есть пин/спрос (кеш у читателей). Важно: критичные каталоги/ключи всегда пинятся несколькими независимыми узлами (правило сети). Вложения в чатах: только ссылка-CID; медиа подгружаются по требованию. 4) Репутация и модерация Единицы: жалоба, метка (нежелательное/вредное/спам/пиратское/NSFW и т.п.). Роли: модераторы/арбитры/участники; правила — подписанные документы сервера. Механика: решение «принято/отклонено/в работе», апелляция, аудит-лог (хэши). Распространение: списки white/grey/black — подписанные манифесты, опционально «уважаемые» каталоги (как источники доверия). Приватность: жалобы шифруются до модераторов, публично видны только итоговые метки. 5) UX/Приложение (что видит пользователь) Вкладки: Лента (со статусом сети), Сообщения (DM), Серверы (текст/голос/вики/файлы), Путешествия (каталог), Браузер .alt, Почта, Создать сервер (мастер 4 шага), Репутация, Помощь, Профиль. Мини-профили: аватар, био, роли/стикеры, статусы (свободный текст/эмодзи). Темы: светлая/тёмная + 3–5 акцентных цветов. Конструктор сайтов: блоки (заголовок/текст/картинка/видео(CID)/кнопка/галерея), предпросмотр, экспорт статического сайта. Почта: inbox/sent/drafts, просмотр, «написать», вложения (CID-моки), подсказка-tooltip на иконке. 6) План разработки (этапы, цели, критерии приёмки) Этап 0 — Подготовка (1–2 недели) Цели: каркас репо, базовый UI, переключатель тем, навигация, мок-слои. Деливери: Monorepo/или SPA-репо (React+TS+Tailwind, shadcn/ui доп. при необходимости). Навигация по вкладкам, базовый layout, локализация RU. Вспомогательные утилиты (cls(), хранилище настроек, мок-хранилище данных). Приёмка: сборка без ошибок; переключение вкладок; смена темы; смоук-тест утилиты. Этап 1 — TAL + режимы (2–3 недели) Цели: транспортная абстракция, профили «Анонимный/Быстрый», конфиг-матрица. Деливери: Интерфейсы TAL: детект интерфейсов, измерения, политика путей, hot-failover (моки). Переключатель профиля и применяемые политики (DHT/mDNS/Relay). Панель «Состояние сети» в Ленте (моки метрик). Приёмка: ручные сценарии смены профиля; метрики меняют состояние; политики применяются (в моках/флагах). Этап 2 — Контентный слой (IPLD/IPFS-мок) (2 недели) Цели: CID-хранилище, кеш+LRU, пины/квоты, общий pin-манифест. Деливери: Менеджер кеша с квотами, LRU-эвиктор; UI настроек хранения. Пины (локальные/по манифесту), просмотр занятости. Имитация RS-шардинга для «холодного» (генерация N-частей, сборка M). Приёмка: добавил файл → появился CID, попал в кеш; пин защищает от выселения; квоты работают. Этап 3 — Сообщения (DM) и вложения (2–3 недели) Цели: DM-чаты E2E, вложения как CID (превью), реакции/эмодзи (моки). Деливери: CRDT-журналы сообщений; список/просмотр; прикрепление медиа → CID → превью. Реакции, стикеры, статусы. Приёмка: отправка/получение, сквозной CID-поток, переключение тем/статусов. Этап 4 — Серверы (чаты/голос/вики/файлы) (3–4 недели) Цели: модель сервера как набора каналов; текстовые каналы полностью; голос — мок/WebRTC-заглушка; вики — CRDT-док. Деливери: Структура сервера, роли/права; мастер «Создать сервер»: имя → каналы → роли → зеркала. Текстовые каналы (история, прикрепы-CID), вики-страницы (CRDT), файловая полка (список CID, пины/загрузки). Голос: UI (подключиться/микрофон), мок-состояния. Приёмка: создание сервера; работа каналов; права скрывают каналы; вики редактируется несколькими клиентами (локально). Этап 5 — Браузер .alt + Конструктор сайтов (3 недели) Цели: просмотр статических .alt, конструктор WYSIWYG, экспорт «IPFS-готово». Деливери: Мини-адресная строка, «история», «Опубликовать сайт». Конструктор: палитра блоков, холст, свойства, предпросмотр, экспорт ZIP (index.html+styles.css+manifest.json). Приёмка: создать простую страничку → экспорт → открыть в «Браузер .alt». Этап 6 — Почта + Репутация + Путешествия + Помощь + Профиль (2–4 недели) Цели: довести оставшиеся экраны до MVP. Деливери: Почта: inbox/sent/drafts, compose, вложения(CID-моки), TTL «почтовых узлов» (моки). Репутация: карточки жалоб/меток, фильтры, статусы решений, аудит-лог (хэши). Путешествия: каталог серверов/ботов/мини-приложений, поиск/фильтры. Помощь: wiki/FAQ/tooltip’ы; Профиль: темы/акценты/био/стикеры. Приёмка: ручные сценарии по каждому экрану; сохранение настроек; репутационные метки визуально применяются. Итог MVP: все вкладки кликабельны, данные мокируются, профили режимов переключаются и влияют на политику сети/виджеты, есть экспорт сайтов, DM/серверные чаты работают на CRDT-моках с CID-вложениями. 7) Критерии производительности и UX (для MVP) Навигация между вкладками < 50 мс (кэшированный рендер). Списки (лента/чаты) — виртуализация; 10k элементов не «роняют» fps. Экспорт статического сайта — < 1 с на 20 блоков. Память приложения: < 300 МБ на типичный сценарий (без медиа-кеша). Визуал: современный (Discord-like), тёмная/светлая, реакции/стикеры, тултипы. 8) Тест-матрица (что обязательно проверить) Сетевые профили: Переключение «Анонимный ↔ Быстрый» — политики применяются (флаги TAL/DHT/mDNS/Relay). Отображение «Состояния сети» меняется (иконки/лейблы/подсказки). Контент/хранение: Квоты кеша, LRU-выселение, неприкосновенность пинов. RS-шардинг: N=6, M=4 — файл собирается из 4 частей. DM/Серверы: Отправка текста, прикрепление медиа → CID; превью рендерится. Права ролей скрывают каналы, CRDT-конфликты мержатся. Конструктор/Браузер: Добавление всех типов блоков, предпросмотр, экспорт ZIP, открытие в .alt. Почта: Создание письма, вложения (CID-моки), перемещение между папками, TTL-индикаторы. Репутация: Подача жалобы, решение модерации, отражение метки в UI. 9) Поставки/дистрибуция и обновления Десктоп: Windows (.exe) / macOS (.dmg) / Linux (.AppImage/.deb). Мобила: Android (apk) на втором этапе; iOS — позже как PWA/обходной путь. Обновления: подписанные манифесты (несколько доверенных ключей), двухфазное обновление (старый бандл сохраняется до подтверждения успеха). Никаких «телеметрий наружу» по умолчанию. 10) Риски и как их закрываем Скорость Tor/I2P — ограничение для видео/лайва. Решение: локальные кластеры, адаптивный битрейт, добровольные реле в быстром оверлее (при согласии пользователя). Долговечность контента — зависит от пинов/зеркал. Решение: общий pin-манифест сообществ, «холодное» хранение, подсказки UX «сохранить у себя». Модерация/злоупотребления — решаем на уровне подписанных правил, прозрачных журналов и локальной автономии серверов. Метаданные — минимизация по умолчанию, режим «Анонимный» выключает болтливые механизмы. 11) Что нужно от тебя на старте (быстрый чек-лист) 1. Утвердить матрицу режимов (таблица выше) — всё ок? 2. Подтвердить квоты по умолчанию (кеш 5%, профили 1–2/5–10/20–50%). 3. Зафиксировать первую цель спринта: Этап 0 → Этап 1. 4. Скажи, хочешь ли сразу Виджет «Состояние сети» в Ленте (да/нет, какие поля). 5. Готовы ли названия ролей/меток для Репутации (могу предложить дефолт). 12) Коротко, «как для обывателя» Приложение как Discord+Telegram, только без единого центра. Всё, что пишешь и отправляешь, шифруется на твоём устройстве. Есть два режима: анонимный (повольнее, зато приватнее) и быстрый (шустро в локали, а наружу — с защитой). Видео/файлы не лежат на одном сервере — сами участники временно хранят кусочки. Если всем перестало быть нужно — оно исчезает, как сторис без пинов. Хочешь, чтобы осталось — поставь «сохранить» (пин) или включи зеркало. «Сайты» — это папки с файлами, которые ты собираешь в конструкторе и публикуешь. Они открываются в «Браузере .alt».
