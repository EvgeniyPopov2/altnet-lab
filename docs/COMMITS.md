# Стиль коммитов (Conventional Commits, RU)

**Коротко:** одна строка-заголовок вида  
`<type>(<scope>): <императив, что сделано>` — без точки в конце, до ~72 символов.  
Дальше по желанию — тело (почему/что внутри), потом футер (BREAKING CHANGE, ссылки на issues).

## Типы
- **feat** — новая функциональность.
- **fix** — исправление ошибки.
- **docs** — документация.
- **refactor** — рефакторинг без изменений поведения.
- **perf** — производительность.
- **test** — тесты.
- **build** — сборка/зависимости/упаковка.
- **ci** — CI/CD.
- **chore** — прочее (инфраструктура, метафайлы).
- **revert** — откат коммита.

## Области (scope) для нашего проекта
`discovery`, `systemd`, `tor`, `ipfs`, `onion-fwd`, `scripts`, `docs`, `repo`, `vagrant`, `lab`.

## Правила
- Пиши **в повелительном наклонении**: «добавить», «исправить», «удалить», «вынести».
- Заголовок — что делает патч. В теле — **почему** (кратко, пунктами).
- Русский ок. Кодировка UTF-8 (сконфигурировано).
- Для ломающих изменений добавляй футер:  
  `BREAKING CHANGE: описание`.
- Можно закрывать задачи:  
  `Closes #12`, `Refs #34`.

## Примеры для AltNet
- `docs: добавить BRANCHING.md (ветки main/lab/dev, релизы)`
- `systemd(discovery): исправить ExecStart — прокинуть TOR_PREFIX`
- `tor: вынести bridges.conf в bridges.conf.example`
- `scripts(apply): добавить проверки наличия tar и jq`
- `feat(discovery): профиль anon — HTTP :18081 по умолчанию`
- `fix(discovery): игнорировать пустой PEERS в env`
- `chore(repo): настроить .gitattributes для LF`
- `build(ipfs): поднять kubo до v0.28.0`

## Рекомендуемая структура сообщения
```
<type>(<scope>): <кратко>

— что изменили (1–3 пункта)
— почему это нужно / какой баг закрывает

Closes #123
BREAKING CHANGE: ...
```

## Проверка
- История кратко: `git log --oneline -n 10`
- Детали последнего: `git show --stat`
