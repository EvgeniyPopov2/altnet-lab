# AltNet — Матрица эффективной сессии (ESM) для DM/групп/звонков (v1)

⟦ALTNET/ANCHOR: ESM_MATRIX_V1; STRICTEST_WINS=YES; FAIL_CLOSED=YES; RTC_NO_PUBLIC_STUN=YES⟧

## 1) Зачем этот документ
В AltNet есть два сетевых профиля:
- **Anon**: Tor/I2P, DHT off, mDNS off, relay только свои, payload E2E.
- **Private Fast**: Yggdrasil/WireGuard, DHT off/локально, mDNS в LAN/mesh, relay только свои, payload E2E.

При общении участников в разных профилях критично не “сломать” анонимность Anon через:
- прямые соединения,
- ICE/STUN утечки в RTC,
- публикацию/обмен “быстрыми” адресами,
- автодеградации политики (downgrade).

Этот документ фиксирует:
- **алгоритм выбора эффективного режима сессии (ESM)**,
- **матрицу совместимости**,
- **правила fail-closed**,
- **инварианты/тесты**,
- **что показываем в UI (Состояние сети / шапка чата / экран звонка)**.

## 2) Термины
- **Профиль (Profile)**: Anon или Private Fast.
- **Подложка/оверлей (Overlay family)**:
  - Anon-family = {Tor, I2P}
  - Fast-family = {Yggdrasil, WireGuard}
- **ESM (Effective Session Mode)**: вычисленный режим для КОНКРЕТНОЙ сессии (чат/звонок/голосовой канал),
  который может отличаться от глобального профиля устройства.
- **Contact Bundle**: «пакет контакта» (минимум: identity, prekeys, rendezvous-адреса по оверлеям, allow-list relays/TURN).
- **Rendezvous-адрес**: адрес входа/точка встречи (например onion/i2p dest или ygg/wg endpoint).
- **Fail-closed**: при сомнении/ошибке/недоступности нужного оверлея — НЕ отправляем/НЕ звоним.

## 3) Жёсткие принципы (MUST)
### 3.1 Strictest-wins (самый строгий доминирует)
Если хотя бы одна сторона “требует Anon-family” (потому что у неё нет fast-endpoints или она явно помечает контакт как Anon-only),
то **ESM = Anon-family** для этой сессии.

Иначе (если обе стороны доступны в Fast-family), ESM может быть Fast-family.

### 3.2 E2E — всегда (транспорт не считается достаточным)
Транспортное шифрование (Noise/TLS/SRTP) НЕ заменяет E2E.
Если E2E-контекст не установлен — отправка/сигналинг/медиа блокируются (fail-closed).

### 3.3 Никаких “публичных” STUN/relay/TURN
- В Anon-family: STUN запрещён; RTC только в режиме **relay-only** через TURN из allow-list, достижимый через Tor/I2P.
- В Fast-family: публичные STUN/TURN запрещены; только self/allow-list в оверлее.

## 4) Матрица совместимости (DM и звонки)

Обозначения:
- ✅ возможно автоматически
- ⚠️ возможно, но с деградацией/переключением ESM (compat)
- ⛔ fail-closed (по умолчанию)
- (U) = требуется явное действие пользователя (опционально, если мы вообще допускаем)

### 4.1 DM (сообщения)
| Локальный профиль | У контакта есть только Anon-endpoint | У контакта есть только Fast-endpoint | У контакта есть оба |
|---|---|---|---|
| Anon | ✅ ESM=Anon | ⛔ (нет безопасного пути без раскрытия IP Anon) | ✅ ESM=Anon (не использовать fast-endpoint) |
| Fast | ⚠️ ESM=Anon (Tor/I2P “compat” для этого чата) | ✅ ESM=Fast | ✅ ESM=Fast (но можно принудить ESM=Anon per-chat) |

### 4.2 RTC (звонки 1:1)
| Локальный профиль | Контакт Anon-only | Контакт Fast-only | Контакт dual |
|---|---|---|---|
| Anon | ✅ ESM=Anon + ICE relay-only | ⛔ | ✅ ESM=Anon + ICE relay-only |
| Fast | ⚠️ ESM=Anon + ICE relay-only (Tor compat) | ✅ ESM=Fast (host/relay в оверлее) | ✅ ESM=Fast (или ESM=Anon per-call) |

### 4.3 Группы/серверы
Правило по умолчанию (MVP):
- Текстовые группы могут существовать в обоих режимах.
- Голос/видео:
  - если “группа Anon” → все участники должны уметь ESM=Anon для звонка (иначе fail-closed на этапе join).
  - если “группа Fast” → Anon-профиль не входит (fail-closed), чтобы не провоцировать утечки и не создавать скрытый downgrade.

Опционально позже:
- “двухконтурные” группы (fast + anon комнаты как отдельные каналы).

## 5) Как Fast-пользователь “входит” в Tor/I2P (compat mode)

### 5.1 Режим совместимости (compat) — это НЕ смена глобального профиля
Compat включается:
- per-chat / per-call,
- автоматически, если контакт Anon-only,
- и отображается в UI как “Путь: Tor (совместимость)”.

### 5.2 Tor-compat (дефолт для MVP)
Алгоритм (логика):
1) При попытке открыть чат/звонок с контактом Anon-only:
   - если локальный Tor-клиент не запущен → запускаем.
2) Ждём bootstrap Tor до “готово” (иначе fail-closed).
3) Все соединения для этого чата/звонка идут через SOCKS Tor.
4) Включаем **изоляцию потоков по контакту**:
   - отдельные SOCKS-учётки (username/password) на контакт,
   - либо отдельный SOCKS port на контакт (если так проще),
   - чтобы минимизировать корреляцию трафика между разными контактами.
5) В логах НЕ писать кандидаты ICE/адреса/сырой SDP.

Результат:
- Fast-пользователь не получает “полную анонимность личности”, но для данного взаимодействия он не раскрывает Anon-участника,
  и не создаёт утечки через RTC/ICE.

### 5.3 I2P-compat (позже, опционально)
I2P тяжелее по UX и ресурсам. Для MVP допускаем только Tor-compat как дефолт.
I2P добавляем как альтернативный backend, если Tor недоступен/блокируется.

## 6) RTC-политика (anti-leak) — MUST
Мы используем WebRTC-медиа (SRTP), а E2E живёт на сигнальном уровне AltNet (и далее, при необходимости, на медиа-уровне).  

### 6.1 Настройки для ESM=Anon
- `iceTransportPolicy = "relay"` (только relay-кандидаты)
- STUN = выключен (никаких публичных STUN вообще)
- TURN:
  - только allow-list,
  - предпочтительно TURN over TCP/TLS (из-за Tor),
  - адрес TURN должен быть достижим через Tor (например, onion endpoint для control/data каналов).
- Запрещаем “direct p2p” даже если оно “вдруг возможно”, потому что это главный путь утечки.

Fail-closed:
- если TURN недоступен/не из allow-list → звонок не стартует, UI показывает причину.

### 6.2 Настройки для ESM=Fast
- Host-кандидаты допустимы ТОЛЬКО в пределах Ygg/WG интерфейсов.
- Публичные STUN/TURN запрещены.
- TURN (если нужен) — только self/allow-list в оверлее.

## 7) UI: что показываем пользователю (минимум v1)
### 7.1 В шапке чата / экране звонка
- “Профиль устройства: Anon/Fast”
- “Эффективная сессия: Anon (Tor compat) / Fast (Ygg/WG)”
- “E2E: установлено / не установлено (отправка заблокирована)”
- Для звонка:
  - “RTC: relay-only (Anon)” или “RTC: overlay host/relay (Fast)”
  - индикатор качества (RTT/Jitter/Loss) как агрегат TAL

### 7.2 В «Состоянии сети» (Лента)
- активный профиль
- enforcement status: OK/Violation
- активные транспорты (Tor/I2P или Ygg/WG)
- Leak-Guard:
  - прямые WAN-коннекты: 0/…
  - DNS вне профиля: 0/…
  - STUN/ICE вне профиля: 0/…
- “Последнее переключение (hot-failover): причина”

## 8) Инварианты и тесты (минимум)
### 8.1 Policy engine / TAL
- ESM-001: Если контакт Anon-only → ESM=Anon (даже если устройство в Fast).
- ESM-002: Если ESM=Anon → любые прямые WAN sockets запрещены.
- ESM-003: Любая попытка включить публичный DHT/relay/TURN вне allow-list → DENIED (fail-closed).
- ESM-004: Любая отправка без E2E-контекста → DENIED.

### 8.2 RTC anti-leak
- RTC-001: В ESM=Anon `iceTransportPolicy=relay`, STUN=off.
- RTC-002: В ESM=Anon список ICE серверов содержит только allow-list TURN.
- RTC-003: Логи не содержат SDP/ICE кандидатов/локальных адресов.
- RTC-004: При недоступности TURN (Anon) — звонок не стартует (fail-closed).

### 8.3 UI-инварианты
- UI-001: Если E2E не установлено — UI явно показывает “отправка заблокирована”.
- UI-002: Если включён compat (Tor для Fast) — это видно пользователю (без скрытых режимов).

## 9) Выбор реализации (варианты) — и дефолт
Вариант A (дефолт, MVP): **strictest-wins + Tor-compat для Fast per-chat/per-call**.
- Плюсы: проще, предсказуемо, минимизирует риск утечек.
- Минусы: скорость Tor.

Вариант B: “dual-stack relay” (узел, который говорит и с Tor, и с Ygg) как мост.
- Плюсы: быстрее для Fast.
- Минусы: сложнее, риск корреляции на мосту, нужен доверенный узел.

Вариант C: специальные “rendezvous” протоколы/MLS/софистик. пэддинг.
- Плюсы: максимум.
- Минусы: не MVP.

По умолчанию принимаем **Вариант A**.
