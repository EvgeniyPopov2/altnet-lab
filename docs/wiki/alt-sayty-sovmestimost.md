# Сайты Alt: проверенная совместимость и границы

Снимок по исходникам 24.11.2026. Статус отдельных функций необходимо дополнительно подтверждать испытаниями. Документ не является заявлением о готовности сетевой публикации или независимом аудите безопасности.

## Где сейчас находится сайт

Кнопка публикации сохраняет HTML и страницы в хранилище браузера на текущем устройстве. `alt://site/...` в этом сценарии — адрес локальной записи, а не подтверждение отправки в IPFS. Получение сайта другим участником, маршрутизация по профилям, проверка целостности полученного содержимого, закрепление и обновление опубликованного имени не реализованы и не проверены как сквозной сценарий.

Конструктор также умеет создать **локальный CAR-пакет** сайта с настоящим CIDv1; другой участник может открыть полученный файл в `.alt`, указав CID для сверки. Это перенос файла, а не сетевая публикация. Проверка CID подтверждает целостность, но не авторство: адрес необходимо получить по доверенному каналу. После проверки страницы сохраняются локально и открываются через существующую песочницу. Испорченные данные, неверный корень и посторонние блоки отклоняются до записи в хранилище.

Добавлен экспериментальный приём CAR от **указанного пользователем onion-шлюза IPFS**. Локальный клиент принимает только проверенный по контрольной сумме onion v3 и канонический CID сайта, открывает соединение исключительно через локальный SOCKS управляемого Tor и запрашивает `/ipfs/<CID>?format=car`. DNS вне Tor, редиректы, прямой резервный маршрут и сжатые ответы не используются; размер и время ограничены, одновременно разрешена одна загрузка. Локальный API требует сессионный токен, правильные Host и Origin. Сайт сохраняется и показывается только после проверки содержимого в браузере. Если Tor недоступен или приостановлен, запрос завершается ошибкой.

Это **не собственная сетевая публикация и не поиск участников AltNet**: получатель должен знать работающий onion-шлюз с этим CID и отдельно получить доверенный CID. Проверки транспорта и пользовательского интерфейса выполнены с локальной имитацией SOCKS и шлюза; реальный обмен через Tor между независимыми участниками пока не подтверждён. Доступность, авторство, конфиденциальность сайта и защита от корреляции трафика не гарантируются. Для настоящей публикации ещё необходимы управление собственным onion-сервисом и его ключами, жизненный цикл при смене мостов, распространение адресов и маршруты других профилей. Тесты: `tests/site-onion-transport.py`, `ui/altnet-ui/tests/onion-car-ui.mjs` и `ui/altnet-ui/tests/onion-car-integration.mjs`.

Формат использует корень DAG-CBOR со ссылками IPLD на блоки страниц размером до 256 КиБ. Перед открытием повторно проверяются SHA-256 каждого блока, связи, размеры и имена страниц; пакет ограничен 500 страницами, 16 МиБ на страницу и 64 МиБ суммарного HTML. Неизменённая страница экспортируется без временной метки, чтобы не менять CID при повторной сборке. Подпись автора, отзыв и обновляемое имя пока не реализованы.

Формат испытан с двумя отдельными Kubo 0.29.0 во временном сетевом пространстве с единственным loopback-интерфейсом: без bootstrap, DHT, mDNS и relay. Первый узел импортировал и закрепил CAR, второй получил граф, после чего страницы и хеши снова проверены. Это проверка совместимости и передачи блоков, не проверка маршрута Tor/Yggdrasil, безопасности старой версии Kubo или связи между устройствами пользователей. Библиотеки и форматы: [CID/IPLD](https://docs.ipfs.tech/concepts/content-addressing/), [CAR](https://github.com/ipld/js-car), [Kubo DAG import](https://docs.ipfs.tech/reference/kubo/rpc/#api-v0-dag-import).

Повторяемые проверки находятся в `ui/altnet-ui/src/core/sites/ipfsSitePackage.test.ts`, `ui/altnet-ui/tests/ipfs-car-ui.mjs`, `tests/ipfs-site-fixture.ts` и `tests/ipfs-two-nodes.py`. Последний тест требует отдельного сетевого пространства Linux с включённым только loopback и изолированных тестовых репозиториев; он отказывается запускаться при наличии других интерфейсов. Находящаяся в стенде версия Kubo используется только в этом изолированном испытании, её нельзя считать рекомендованной версией для выпуска.

IPFS может распространять файлы сайта по содержимому, но сам по себе не обеспечивает доверие к автору, секретность или постоянную доступность. Для обновлений нужен отдельно спроектированный проверяемый механизм имён и подписей; политика доступа и транспорта не заменяется наличием CID.

## HTML, код и интерактивность

| Возможность | Что делает текущий код |
|---|---|
| Code | Показывает введённый код текстом, не выполняет его. |
| HTML (Safe) | Допускает ограниченную форматированную разметку. Скрипты, обработчики событий, стили, формы, iframe и медиа удаляются. |
| Вкладки | Переключаются средствами HTML/CSS; нужна поддержка используемого CSS браузером. |
| Аккордеон, карусель, таймеры, панели, появление | Используют фиксированный код AltNet, добавляемый экспортером и разрешённый по хешу CSP. Автор сайта не может добавить таким способом свой код. При отсутствии соответствующего обработчика часть интерактивности не работает. |
| Поиск | Локальный индекс и обработчик отсутствуют; поиск в локальном просмотре отключён с пояснением. Обычная экспортная форма требует отдельного обработчика. |
| Рейтинг | Выбор действует в текущем просмотре; сбор и сохранение голосов не подключены. |
| Поделиться | Передача и копирование адреса из виджета в локальном просмотре отключены. Адрес локальной записи не является сетевой ссылкой. |
| Изображения и видео | Локальный просмотр разрешает только поддерживаемые data-ресурсы. Внешние адреса не загружаются; доступность ресурсов в будущей сети не подтверждена. |
| Карта | Есть встроенная обзорная карта. Подробная внешняя карта и внешняя ссылка в локальном просмотре недоступны. |
| SoundCloud | Внешний плеер и ссылка в локальном просмотре недоступны. |
| Ссылки | Якоря и ссылки на страницы одной локальной публикации поддерживаются. Прочие ссылки в локальном просмотре блокируются. |
| Shortcode | Старый тип не имеет ветки экспорта; неподдерживаемые типы нельзя выдавать за работающие. |

Сетка, оформление и перечисленные ограничения не означают, что каждое сочетание настроек всех виджетов уже проверено на каждом устройстве. См. также [матрицу конструктора](konstruktor-elementor.md).

## Модель безопасности и оставшаяся работа

Локальная страница открывается в iframe с `sandbox="allow-scripts"`, без `allow-same-origin`; локальный CSP запрещает сетевые подключения, отправку форм, вложенные фреймы и inline-обработчики. Санитизатор удаляет пользовательские скрипты и внешние источники, а известные встроенные сценарии сравниваются с точным содержимым и разрешаются по хешу. Данные всплывающих окон дополнительно ограничиваются, удаляются SVG-анимации, способные изменять адреса. Это защитные меры, а не доказательство отсутствия уязвимостей.

В рабочей версии локального просмотра скрипты и стили выносятся в локальные `data:`-ресурсы: код проходит проверку целостности и ограничен хешами CSP, inline-скрипты, атрибуты событий и inline-стили запрещены политикой. Стили разбираются CSSOM с ограничениями размера, числа правил и глубины; `@import` и неподдерживаемые директивы отбрасываются. При переносе атрибутов стиля сохраняется приоритет обычных значений и `!important`. Это изменение касается локального просмотра и не подтверждает безопасность сетевой загрузки сайтов. Обычный экспорт самостоятельного HTML имеет другую политику. Нужны проверка всех поддерживаемых оболочек, независимый аудит и завершение профильного транспорта до заявления о соответствии всей платформы доктрине.

24.11.2026 DOMPurify обновлён до 3.5.0 после проверки npm audit. Проверка производственных зависимостей после обновления не показала известных предупреждений; это снимок на дату проверки, а не независимый аудит приложения.

При автоматическом открытии локальной страницы разработки также наблюдались запросы к адресам компонентов AdGuard и Kaspersky; тест заблокировал эти запросы. Их точный источник, влияние на приватность и поведение установленной оболочки отдельно не исследованы. Это наблюдение относится к тестовому окружению и не доказывает, что запросы исходили от содержимого сайта.

Динамические сайты возможны как набор заранее реализованных ограниченных возможностей платформы: например, переключение вкладок, поиск по локальному индексу и просмотр обновляемых подписанных данных. Для каждого действия нужны конкретный источник и схема данных, права, квоты, проверенная изоляция и безопасный транспорт. Запись отзывов или совместное редактирование потребуют отдельного протокола хранения, идентификации, модерации и синхронизации; простая публикация статического HTML не создаёт эту инфраструктуру.
