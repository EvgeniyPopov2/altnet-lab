# Сайты Alt: проверенная совместимость и границы

Снимок по исходникам 24.11.2026. Статус отдельных функций необходимо дополнительно подтверждать испытаниями. Документ не является заявлением о готовности сетевой публикации или независимом аудите безопасности.

## Где сейчас находится сайт

Кнопка публикации сохраняет HTML и страницы в хранилище браузера на текущем устройстве. `alt://site/...` в этом сценарии — адрес локальной записи, а не подтверждение отправки в IPFS. Получение сайта другим участником, маршрутизация по профилям, проверка целостности полученного содержимого, закрепление и обновление опубликованного имени не реализованы и не проверены как сквозной сценарий.

IPFS может распространять файлы сайта по содержимому, но сам по себе не обеспечивает доверие к автору, секретность или постоянную доступность. Для обновлений нужен отдельно спроектированный проверяемый механизм имён и подписей; политика доступа и транспорта не заменяется наличием CID.

## HTML, код и интерактивность

| Возможность | Что делает текущий код |
|---|---|
| Code | Показывает введённый код текстом, не выполняет его. |
| HTML (Safe) | Допускает ограниченную форматированную разметку. Скрипты, обработчики событий, стили, формы, iframe и медиа удаляются. |
| Вкладки | Переключаются средствами HTML/CSS; нужна поддержка используемого CSS браузером. |
| Аккордеон, карусель, таймеры, панели, появление | Используют фиксированный код AltNet, добавляемый экспортером и разрешённый по хешу CSP. Автор сайта не может добавить таким способом свой код. При отсутствии соответствующего обработчика часть интерактивности не работает. |
| Поиск | Локальный индекс и обработчик отсутствуют; поиск в локальном просмотре отключён с пояснением. Обычная экспортная форма требует отдельного обработчика. |
| Рейтинг | Выбор действует в текущем просмотре; сбор и сохранение голосов не подключены. |
| Поделиться | Передача и копирование адреса из виджета в локальном просмотре отключены. Адрес локальной записи не является сетевой ссылкой. |
| Изображения и видео | Локальный просмотр разрешает только поддерживаемые data-ресурсы. Внешние адреса не загружаются; доступность ресурсов в будущей сети не подтверждена. |
| Карта | Есть встроенная обзорная карта. Подробная внешняя карта и внешняя ссылка в локальном просмотре недоступны. |
| SoundCloud | Внешний плеер и ссылка в локальном просмотре недоступны. |
| Ссылки | Якоря и ссылки на страницы одной локальной публикации поддерживаются. Прочие ссылки в локальном просмотре блокируются. |
| Shortcode | Старый тип не имеет ветки экспорта; неподдерживаемые типы нельзя выдавать за работающие. |

Сетка, оформление и перечисленные ограничения не означают, что каждое сочетание настроек всех виджетов уже проверено на каждом устройстве. См. также [матрицу конструктора](konstruktor-elementor.md).

## Модель безопасности и оставшаяся работа

Локальная страница открывается в iframe с `sandbox="allow-scripts"`, без `allow-same-origin`; локальный CSP запрещает сетевые подключения, отправку форм и вложенные фреймы. Санитизатор удаляет пользовательские скрипты и внешние источники, а известные встроенные сценарии сравниваются с точным содержимым и разрешаются по хешу. Это защитные меры, а не доказательство отсутствия уязвимостей.

Сейчас есть существенное расхождение с §3.4 действующей доктрины: локальный просмотр допускает inline-стили через `style-src 'unsafe-inline'`, а доверенные inline-скрипты разрешаются по хешу. Доктрина требует запрета inline-скриптов и стилей. Для соответствия нужна новая проверенная схема доставки доверенного кода и стилей без произвольного исполнения, сохранение изоляции и проверки профиля, а также регрессионные и независимые проверки. Нельзя считать нынешний механизм принятым по доктрине только из-за хеша.

При автоматическом открытии локальной страницы разработки также наблюдались запросы к адресам компонентов AdGuard и Kaspersky; тест заблокировал эти запросы. Их точный источник, влияние на приватность и поведение установленной оболочки отдельно не исследованы. Это наблюдение относится к тестовому окружению и не доказывает, что запросы исходили от содержимого сайта.

Динамические сайты возможны как набор заранее реализованных ограниченных возможностей платформы: например, переключение вкладок, поиск по локальному индексу и просмотр обновляемых подписанных данных. Для каждого действия нужны конкретный источник и схема данных, права, квоты, проверенная изоляция и безопасный транспорт. Запись отзывов или совместное редактирование потребуют отдельного протокола хранения, идентификации, модерации и синхронизации; простая публикация статического HTML не создаёт эту инфраструктуру.
