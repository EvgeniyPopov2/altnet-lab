AltNet UI & Visual Design Doctrine
(Discord + Telegram + Elementor: high-fidelity reference synthesis)
Version 1.0 — 11 December 2025

1. Purpose and scope
This document defines the UI and visual design doctrine for the AltNet product. It is intentionally prescriptive: the goal is to enable pixel-close replication of reference UI fragments from Discord, Telegram, and Elementor while keeping AltNet brand-distinct. It includes design tokens, component specs, layout grids, iconography rules, and motion guidelines.
In-scope: desktop app UI (primary), responsive web UI, and mobile-aligned patterns.
Out of scope: copying third-party brand assets (logos, wordmarks) or protected trade dress.
Reference products: Discord, Telegram, Elementor.
2. Design principles
Principle
Meaning in AltNet
Modern density control
Discord-style adjustable density: compact navigation + readable chat; no 90s “flat blocks”.
Layered surfaces
Dark UI with distinct elevation layers; subtle borders; careful contrast management.
Frictionless navigation
Telegram-like speed and clarity: minimal chrome, fast scan, strong hierarchy.
Builder ergonomics
Elementor-like left panel, predictable controls, consistent icon buttons, and live preview canvas.
Motion as feedback, not decoration
Short, consistent transitions; no long/flashy animations.
Accessibility by default
Keyboardable UI, focus rings, readable typography, contrast-aware color usage.

3. Visual language overview
AltNet UI combines three reference archetypes:
• Discord: multi-pane information architecture, “dark with depth”, compact icon navigation.
• Telegram: message list clarity, bubble rhythm, minimal visual noise.
• Elementor: builder panel patterns, control grouping, and design-token mindset.
4. Design tokens
Tokens are the single source of truth. Implement them as CSS variables / theme JSON and use them everywhere (no hard-coded colors or ad-hoc font sizes).

6. Component specifications
This section is intentionally concrete. If you build components differently, AltNet will look inconsistent and dated.
6.1 Buttons
Button anatomy: label (14 px / 600), optional left icon (16–18 px), height 36 or 40, horizontal padding 12–16, radius 8.
States: default, hover, pressed, disabled, loading. All transitions 120–180 ms.
6.2 Inputs and search
Inputs use a filled dark surface with subtle border. Search is a key visual element in Discord/Telegram: compact height, strong placeholder color, and clear focus ring.
6.3 Lists
Lists are the dominant pattern in Discord (channels) and Telegram (chats). Use consistent row heights and strong hover/active states. Row: 40–44 px height, left padding 12–16, icon 16–18, title 14/600, meta 12/400.
6.4 Chat message layout
Adopt Telegram clarity and Discord threading cues:
• Timestamp and author are visually secondary, but scannable.
• Message text line height 20 px (for 14 px size).
• Reactions are compact chips with subtle border; hover reveals add-reaction.
• Attachments are cards: image/video preview + metadata; radius 12.
6.5 Panels and modals
Panels: radius 12, border 1 px subtle, background --surface-1.
Modals: max width 560–720 px, padding 24, header with title + close icon, backdrop 40–60% opacity.
6.6 Builder mode (Elementor-inspired)
Builder mode is a distinct workflow with strong affordances:
• Left panel: tabs, searchable widget library, collapsible sections.
• Canvas: clean background, selection outlines, inline controls.
• Inspector: typography/color controls using design tokens; every control shows the token name when applicable.
• Accent: --brand-builder used for selection outlines, active tool, and key CTAs (sparingly).
7. Iconography
Pick ONE icon family and stick to it. Mixing styles is the fastest way to make the UI look cheap. Preferred: modern rounded outline icon set (e.g., Lucide, Phosphor, Remix) with consistent stroke.

Micro-interactions:
• Nav rail: hover background + subtle scale (1.00 → 1.02) on icon container.
• Buttons: press down (scale 0.98) + shadow reduction.
• Toasts: slide up 12 px + fade.
• Tooltips: fade + 4 px translate.
9. Backgrounds and visual polish
A modern UI is not only colors. Add controlled texture and depth:
• Subtle noise overlay (2–4% opacity) on dark backgrounds to avoid banding.
• Very soft gradient in the app background (value shift 2–4%).
• Blurred “glass” surfaces only in limited contexts (popovers, top bars) to avoid performance issues.
10. Screenshot-to-spec workflow (pixel-close matching)
When you provide a screenshot fragment (Discord/Telegram/Elementor), we will convert it into a replication spec using this template.
Identify platform and context (desktop/mobile, theme, density).
Measure key dimensions: row heights, paddings, radii, font sizes (use a ruler tool).
Sample 8–12 colors: backgrounds, surfaces, borders, text, accents; map onto token ladder.
Extract typography: size/weight/line height; identify if system font or custom.
Decompose into components: list row, button, input, chip, avatar, etc.
Specify motion: what transitions occur on hover/open/close and approximate timing.
Produce a “Replica Card” with: tokens + component overrides + implementation notes.
